# PBF Contour Limitations

## Why contours stop at zoom 14

The outdoor style uses two contour approaches:

1. **PBF vector tiles** (z12–14) — served by `contour-mvt-server` from localhost
2. **Plugin contours** (z15+) — generated client-side by `maplibre-contour`

### PBF ceiling at zoom 14

Each PBF contour tile is generated by running marching squares over a **512×512 pixel DEM grid**. The geometry of each contour line is derived from pixel boundaries in that grid.

At zoom 14, a 512×512 tile covers ~1.2 km² — the pixel boundaries are small enough that 5m contour lines look smooth.

At zoom 15, the same 512 pixels cover only ~0.6 km². The contour lines start to expose the **underlying DEM pixel grid**, producing visible stair-stepping. The vector geometry literally traces pixel edges, and at this scale those edges are large enough to see.

This is a fundamental limitation of server-side vector tile generation from raster DEM data — the output can never exceed the resolution of the source grid.

### TrailSplits API also caps at z12

Before switching to the local contour server, the style used the TrailSplits contour API (`api.trailsplits.com`). That service returns **empty tiles at z13+** (200 OK, 0 bytes). The configured `maxzoom: 14` caused MapLibre to request tiles that didn't exist — contours appeared to stop working above z12.

### The plugin solution for high zooms

`maplibre-contour` works differently — it runs marching squares **on the GPU** in the browser at render time, reading the raw DEM raster directly. Since it always reads the native DEM tile for whatever zoom the map is at, it avoids the pixel-boundary artifact entirely. As you zoom in, it reads higher-resolution DEM tiles (up to the DEM source's maxzoom of 15), producing smooth contours at any zoom level.

### Hybrid approach

| Zoom | Method | Source | Detail |
|------|--------|--------|--------|
| 12–14 | PBF tiles | `localhost:11001` | 20m → 5m intervals, zoom-dependent styling, labels |
| 15+   | Plugin (GPU) | Mapterhorn DEM via `mlcontour://` | Client-side generation, no server load |

The PBF tiles handle the mid-zoom range efficiently (compact vector tiles, full styling control). The plugin takes over at high zooms where server-side vector generation would look blocky.
