# PBF Contour Mode

When `CONTOURS_USE_PLUGIN = false` in `scripts/build.mjs`, the outdoor style uses
server-generated PBF vector tiles for contour lines — no client-side plugin needed.

## Source Zoom Limits

The default PBF source is the **TrailSplits contour API** which caps at **z12**:

```
https://api.trailsplits.com/tiles/v1/contours/current/{z}/{x}/{y}.pbf
```

For higher zoom detail, you can switch to a local
[contour-mvt-server](https://github.com/acalcutt/contour-mvt-server) which
serves up to **z14**:

```js
const CONTOUR_PBF_TILE_URL = 'http://localhost:11001/contours/terrain/{z}/{x}/{y}.pbf'
```

### Why PBF tiles hit a ceiling

Each PBF contour tile is generated by running marching squares over a
**512×512 pixel DEM grid**. The geometry of each contour line follows pixel
boundaries in that grid.

At zoom 14 the ~1.2 km² tiles are small enough that 5m contours look
smooth. At zoom 15 the same 512 pixels cover only ~0.6 km² and the
**underlying DEM pixel grid** becomes visible as stair-stepping in the
vector lines. This is a fundamental limit of server-side contour
generation from raster DEM data.

TrailSplits additionally returns empty tiles at z13+ (200 OK, 0 bytes).

## Plugin Mode for High Zoom

For smooth contours at any zoom level, switch to the **maplibre-contour
plugin** by setting `CONTOURS_USE_PLUGIN = true` in `scripts/build.mjs`.
The plugin runs marching squares on the GPU at render time, reading
native-resolution DEM tiles on demand — no pixel-boundary artifacts, no
server processing.

## Units

PBF labels use the build-time constant `CONTOUR_PBF_UNITS`:

| Value      | Label format | Example  |
|------------|-------------|----------|
| `'metric'` | `120m`      | 120 m    |
| `'imperial'` | `394ft`   | 394 ft   |

Unlike the plugin mode, PBF has no runtime entry point — units are baked
into the style at build time. Toggle `CONTOURS_USE_PLUGIN` and rebuild to
switch implementations.
